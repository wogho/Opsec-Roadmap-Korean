# 인증과 계정 복구

## 인증 기준선

서비스마다 고유하고 충분히 긴 비밀번호를 비밀번호 관리자에서 생성·보관한다. 임의의 복잡성 규칙이나 근거 없는 주기적 변경보다 유출·피싱·재사용을 줄이는 데 집중한다. 유출 정황, 공유 실수, 단말 침해가 있으면 즉시 변경하고 세션을 폐기한다.

지원된다면 피싱 저항성이 있는 패스키 또는 FIDO2 보안 키를 우선한다. TOTP와 문자 코드는 비밀번호만 쓰는 것보다 유용할 수 있지만, 사용자가 코드를 공격자 사이트에 입력하게 만드는 실시간 피싱에는 저항하지 못한다. 중요한 계정은 두 개 이상의 등록 수단을 서로 다른 장소에 보관한다.

## 세션과 복구

강한 로그인도 이미 발급된 세션 쿠키가 탈취되면 우회될 수 있다. 활성 세션, 신뢰 기기, OAuth 연동 앱, 앱 비밀번호를 정기 검토하고 사건 시 전체 세션을 폐기한다.

복구 채널은 인증의 뒷문이 아니라 동일한 보안 경계다. 복구 이메일·전화·백업 코드를 독립적으로 보호하고, 지원센터가 요구하는 정보와 계정 잠금 절차를 미리 확인한다. 복구 코드와 비밀번호 데이터베이스를 같은 단말·같은 클라우드 계정에만 두지 않는다.

## 검증

실제 계정을 위험에 빠뜨리지 않는 범위에서 연 2회 복구 절차를 연습한다. 보안 키 분실, 휴대전화 교체, 비밀번호 관리자 잠금, 담당자 부재를 가정하고 복구 시간과 실패 지점을 기록한다.
