# 파일 수신, 검증, 공유

## 수신

확장자와 MIME 유형을 모두 의심하고, 예상하지 않은 파일은 보낸 사람에게 별도 채널로 확인한다. 외부 입력을 처리하는 뷰어를 최신 상태로 유지하며 매크로·스크립트·자동 실행을 기본 차단한다. 고위험 파일은 격리된 분석 환경에서 열되, 격리가 완전한 경계라고 가정하지 않는다.

## 분석 서비스

해시 평판 조회와 로컬 검사를 먼저 사용한다. VirusTotal 같은 공개·표준 분석 서비스에 업로드한 샘플은 커뮤니티나 고객과 공유될 수 있으므로 기밀·개인·고객 파일을 올리지 않는다. 민감 자료는 계약과 보존 범위가 확인된 사설 분석 또는 내부 환경을 사용한다. 탐지 없음은 안전 판정이 아니다.

## 1. 위협 모델과 처리 원칙

파일은 내용과 실행 행위를 동시에 운반한다. 실행 파일뿐 아니라 PDF, Office 문서, 이미지, 압축 파일, 폰트, 동영상, CAD, 전자서명 문서와 링크 파일도 파서 취약점, 매크로, 외부 참조, 스크립트와 사회공학을 포함할 수 있다. 확장자가 익숙하거나 보낸 사람이 아는 사람이라는 사실만으로 안전하지 않다. 보낸 사람의 계정과 장치가 침해됐을 수 있기 때문이다.

파일 처리 목표는 다음 네 가지다.

1. 악성 코드가 일상 단말과 자격 증명에 도달할 가능성을 줄인다.
2. 원본의 출처·무결성과 수신 맥락을 확인한다.
3. 분석 과정에서 기밀 파일과 개인정보가 외부 서비스로 유출되지 않게 한다.
4. 필요한 수신자에게만 정확한 버전을 전달하고 만료·철회·복구를 관리한다.

탐지 엔진 수를 늘리는 것보다 **출처 확인 → 분류 → 정적 확인 → 격리 실행 → 공유 통제**의 단계와 중단 조건이 중요하다. 분석할 필요가 없는 예상 밖 파일은 열지 않고 발신자에게 독립 채널로 확인한다.

## 2. 수신 채널과 출처 확인

### 2.1 예상 여부

파일명, 보낸 사람, 업무 맥락, 예상 형식과 전달 시점을 확인한다. “급한 견적”, “계정 정지”, “회의록 수정”처럼 행동을 재촉하는 메시지는 발신 계정이 정상이어도 별도 채널로 확인한다. 회신 버튼을 그대로 사용하면 공격자가 만든 대화에 답할 수 있으므로 기존 주소록이나 이미 합의한 채널을 이용한다.

### 2.2 전송 경로

이메일 첨부, 메신저, 협업 링크, USB, 코드 저장소, 패키지 레지스트리와 웹 다운로드는 서로 다른 로그·보존·검증 수단을 가진다. 단축 URL과 리디렉션 뒤의 최종 도메인, 공유 링크의 소유 조직, 파일 버전과 권한을 확인한다. CDN 주소라고 해서 게시자가 신뢰되는 것은 아니다.

### 2.3 서명과 해시

공급자가 공식 사이트와 별도 신뢰 채널에서 제공한 디지털 서명이나 해시를 검증한다. 같은 침해된 웹페이지에 파일과 해시가 함께 있으면 둘 다 바뀔 수 있다. 해시는 파일이 동일함을 보여줄 뿐 파일 자체가 안전하거나 합법적이라는 의미가 아니다. 서명도 서명 키와 배포 계정이 침해되면 악성 파일에 붙을 수 있으므로 보안 공지와 버전을 함께 본다.

## 3. 파일 유형 식별

표시 확장자만 믿지 않는다. 이중 확장자, 오른쪽에서 왼쪽으로 표시되는 문자, 공백·유사 문자와 운영체제가 숨긴 확장자를 확인한다. MIME 유형, 매직 바이트, 압축 내부 목록과 실제 파서를 비교한다. 파일명이 정상 PDF라도 실행 가능한 PE·스크립트일 수 있다.

압축 파일은 중첩, 암호, 심볼릭 링크, 절대 경로, `../` 경로 이동, 비정상적으로 큰 압축 해제 크기와 장치 파일을 점검한다. 압축 폭탄과 경로 순회가 분석 디렉터리 밖 파일을 덮거나 디스크를 채우지 않도록 제한된 환경에서 목록을 먼저 본다. 암호화 압축은 메일 필터를 우회하는 데 자주 악용될 수 있으므로 업무상 필요와 발신자 확인을 요구한다.

문서에는 매크로, OLE 객체, 외부 템플릿, DDE, 내장 파일, JavaScript, 자동 실행과 원격 이미지가 있을 수 있다. 이미지·미디어도 복잡한 코덱과 메타데이터 파서를 사용한다. 어떤 형식도 “열기만 하면 안전”하다고 분류하지 않는다.

## 4. 데이터 분류가 분석보다 먼저다

파일이 공개, 내부, 기밀, 규제·고객 데이터 중 무엇인지 결정한다. 내용뿐 아니라 파일명, 해시, 작성자, 경로와 분석 결과도 민감할 수 있다. 악성 의심 파일에는 피해자 이름, 내부 서버 주소, 토큰과 개인 식별자가 포함될 수 있다.

공개 분석 서비스에 업로드 가능한 조건을 정책으로 정한다. 예를 들어 공개 배포된 설치 파일은 업로드 가능할 수 있지만, 미공개 소스·계약서·고객 문서·침해 로그·자체 개발 바이너리와 개인정보는 승인 없이 외부 업로드하지 않는다. 해시만 조회해도 매우 희귀한 파일의 존재와 관심을 제3자에게 알릴 수 있는지 고위험 상황에서 평가한다.

## 5. 정적 확인 절차

파일을 실행하지 않고 다음을 수집한다.

- 암호학적 해시와 파일 크기
- 실제 형식, 헤더, 아키텍처와 컴파일·작성 메타데이터
- 코드 서명·문서 서명과 인증서 체인
- 압축 내부 파일, 중첩 깊이와 경로
- 문자열, URL, 도메인, IP와 의심 명령
- 매크로·스크립트·외부 참조·내장 객체
- 가져오기 함수, 권한 요구와 지속성 단서
- 공급자 공식 릴리스와 버전 비교

정적 도구도 악성 입력을 파싱하므로 최신 상태의 격리 환경에서 실행한다. 결과 문자열을 터미널에 그대로 출력할 때 제어 문자와 링크가 분석자를 속일 수 있고, 보고서에 비밀이 복제될 수 있다. 증적 저장 위치와 접근 권한을 제한한다.

## 6. VirusTotal의 정확한 사용 범위

VirusTotal은 유용한 외부 인텔리전스·다중 분석 서비스지만, 공격자는 새 해시·암호화 압축·지연 실행·정상 도구 악용으로 탐지를 피하려 할 수 있다. 다음 한계를 전제로 사용한다.

### 6.1 해시 조회

알려진 파일이면 업로드 없이 기존 분석, 최초·최근 관찰, 서명, 행위와 탐지 정보를 얻을 수 있다. 그러나 해시가 없다는 것은 새 파일이거나 비공개일 뿐 안전하다는 뜻이 아니다. 공격자가 작은 변경으로 새 해시를 만들 수 있다.

### 6.2 파일 업로드

일반 공개 업로드는 샘플이 보안 커뮤니티와 고객에게 제공되거나 장기간 보존될 가능성을 고려해야 한다. VirusTotal의 현재 서비스 약관과 개인정보·공유 정책, 조직 계약을 확인한다. 기밀 파일을 “검사만” 한다는 생각으로 업로드하지 않는다.

### 6.3 탐지 결과 해석

한두 엔진의 휴리스틱 탐지는 오탐일 수 있고 0건은 미탐일 수 있다. 탐지명은 공급자마다 다르며 악성 행위의 완전한 분류가 아니다. 서명, 행위 그래프, 접촉 인프라, 파일 관계와 실제 실행 맥락을 함께 본다. 정상 관리 도구도 공격에서 악용될 수 있다.

### 6.4 API와 자동화

API 키를 코드·로그·공개 저장소에 넣지 않는다. 쿼터, 데이터 라이선스, 업로드 금지 분류와 승인 절차를 자동화에 반영한다. 자동 업로드 에이전트가 모든 첨부를 외부로 보내지 않는지 시험한다. 응답 결과는 시점이 지난 캐시일 수 있으므로 분석일과 엔진 상태를 기록한다.

## 7. 로컬·사설 분석

기밀 파일은 승인된 로컬 스캐너, 사설 샌드박스, EDR 또는 계약상 분리된 분석 환경을 사용한다. 도구가 클라우드 평판·샘플 제출·진단 업로드를 기본 활성화하는지 확인한다. ‘로컬 검사’라고 표시돼도 해시나 의심 샘플을 공급자에게 전송할 수 있다.

서명 기반 AV, YARA, 정적 분석, 샌드박스 행위와 네트워크 탐지를 조합한다. 알려진 지표 중심 규칙은 변형·신규 샘플을 놓치므로 이상 행위와 출처·업무 맥락을 함께 본다. YARA 규칙은 성능, 파일 크기 제한, 대상 경로, 오탐과 규칙 출처를 검증한다.

분석 시스템은 생산 계정·비밀·공유 드라이브에 접근하지 않게 한다. 악성 파일이 분석 환경임을 탐지해 대기하거나 정상처럼 행동할 수 있으므로 단일 실행 결과를 최종 결론으로 쓰지 않는다.

## 8. Sandboxie, VM과 Qubes Disposable

Sandboxie 같은 격리는 낯선 프로그램을 일상 환경과 분리해 먼저 관찰하는 통제다. 공격자는 사용자 승인, 공유 폴더·클립보드, 네트워크와 샌드박스·커널 취약점을 우회 경로로 노릴 수 있으므로 애플리케이션 샌드박스 하나를 완전한 경계로 보지 않는다.

### 8.1 애플리케이션 샌드박스

Sandboxie 같은 도구는 파일·레지스트리 쓰기와 프로세스 행위를 격리하는 데 도움을 줄 수 있다. 현재 유지 상태, 지원 OS·브라우저, 관리자 권한, 네트워크와 호스트 파일 접근 정책을 공식 문서에서 확인한다. 커널 취약점, 승인된 파일 복구, 클립보드, 사용자 실수와 샌드박스 탈출 가능성이 남는다.

### 8.2 가상 머신

VM은 별도 OS와 스냅샷을 제공하지만 공유 폴더, 클립보드, 드래그앤드롭, USB, 호스트 통합 도구와 네트워크가 경계를 약화한다. 분석용 VM에는 개인 계정과 비밀을 넣지 않고, 기본 네트워크 차단 후 필요할 때 모니터링된 가상 네트워크만 허용한다. 스냅샷 복귀가 하이퍼바이저·외부 로그·공유 저장소의 변경까지 지우지는 않는다.

### 8.3 Qubes Disposable

Qubes Disposable은 작업 종료 후 루트 파일시스템 변경을 폐기하는 워크플로를 만들 수 있다. 파일을 신뢰 영역으로 복사하는 순간 위험이 이동하며, 템플릿과 dom0, 하드웨어 취약점은 별도다. PDF 변환·열람 등 목적별 Disposable을 쓰고 클립보드·파일 이동을 명시적으로 승인한다.

### 8.4 전용 분석 장치

고위험 샘플은 전용 네트워크·장치에서 다루고 생산망과 물리적으로 또는 강하게 논리 분리한다. 분석 결과와 IOC를 안전한 단방향 또는 검토된 경로로 내보낸다. 무선·Bluetooth·관리 인터페이스와 시간 동기화 같은 숨은 연결도 확인한다.

## 9. 동적 분석과 네트워크 통제

동적 분석 전 실행 시간, 사용자 상호작용, 네트워크, 파일·레지스트리·프로세스·메모리 수집 범위를 정한다. 실제 인터넷을 허용하면 악성 인프라 공격, 추가 페이로드, 데이터 유출과 제3자 피해가 발생할 수 있다. 모의 서비스, DNS sinkhole, 프록시와 패킷 캡처를 이용하고 승인 없이 외부 공격 행위를 유발하지 않는다.

샘플이 지연 실행, 재부팅, 특정 지역·언어, 문서 스크롤·클릭을 요구할 수 있다. 행위가 없었다는 이유만으로 정상 판정하지 않는다. 분석 후 VM을 폐기·재구축하고, 샘플이 호스트나 공유 저장소에 남지 않았는지 확인한다.

## 10. 문서 무해화와 안전한 열람

업무 목적이 내용 열람뿐이라면 원본의 능동 요소를 제거한 새 표현을 만들 수 있다. PDF·Office를 이미지나 단순 PDF로 변환하는 CDR은 매크로·내장 객체를 줄일 수 있지만 서식·서명·숨은 데이터와 증거 가치가 손실될 수 있다. 변환본을 원본과 혼동하지 않도록 해시·라벨·생성 도구·시간을 기록한다.

고위험 문서는 네트워크 없는 읽기 전용 뷰어에서 열고 외부 링크·원격 이미지·폰트 다운로드를 차단한다. 화면 캡처나 수동 전사는 악성 능동 요소를 줄일 수 있지만 민감 내용의 새 사본을 만든다. 법적 증거·포렌식 원본은 임의 변환하지 않고 담당 절차를 따른다.

## 11. 공유 설계

### 11.1 수신자와 권한

‘링크를 아는 모든 사람’보다 명시적 계정, 최소 권한, 만료와 다운로드 제한을 우선한다. 보기 권한도 화면 촬영과 수동 복사를 막지 못한다. 편집·댓글·재공유·외부 초대와 소유권 이전 권한을 별도로 확인한다.

### 11.2 암호화 전달

민감 파일을 암호화할 때 암호와 파일을 같은 메일·메신저 대화에서 보내지 않는다. 이미 합의한 별도 채널로 암호 또는 공개키 지문을 확인한다. 수신자가 파일을 복호화한 뒤 어디에 저장하고 삭제하는지도 합의한다. 암호화 컨테이너는 악성 파일을 안전하게 만들지 않는다.

### 11.3 링크 만료와 철회

만료는 서버 접근을 막을 뿐 이미 다운로드·동기화된 사본을 회수하지 못한다. 공유 전 수신자 최소화와 데이터 최소화가 우선이다. 잘못 공유하면 링크를 철회하고 접근 로그·다운로드 가능성·수신자의 로컬 사본과 추가 전달을 평가한다.

### 11.4 대용량 파일·CDN

Bunny CDN과 공개 업로더는 빠른 배포 수단일 수 있지만 익명·기밀 전달을 자동 제공하지 않는다. 계정, 결제, 업로드 IP, 원본·캐시 로그, 공개 URL과 보존 정책을 평가한다. 민감 자료는 승인된 파일 전송 서비스, 종단간 암호화, 수신자 인증과 계약상 삭제를 사용한다.

AnonFiles 같은 공개 익명 업로더는 소유·가용성·악성 콘텐츠·삭제·법적 요청과 링크 추측 위험을 검증하기 어렵다. 서비스가 사라지거나 도메인이 재사용될 수 있으므로 오래된 링크를 현재 권고하지 않는다.

## 12. 메타데이터와 문서 정화

작성자, 조직, 사용자 이름, 파일 경로, 수정 이력, 댓글, 숨은 시트·슬라이드, GPS, 카메라 일련번호, 썸네일과 임베디드 객체를 확인한다. ‘속성 제거’ 버튼이 모든 형식의 모든 메타데이터를 제거한다고 가정하지 않는다. 정화 전후 파일을 별도 이름으로 만들고 필요한 내용·서명·접근성을 잃지 않았는지 검토한다.

파일명과 폴더 구조도 민감하다. 공유 링크 URL, 압축 내부 경로와 오류 메시지에 프로젝트·고객·사용자 이름이 남을 수 있다. 해시와 워터마크는 수신자 추적에 도움이 될 수 있지만 개인정보와 내부 고유 식별자를 새로 만들며 제거·오탐·강압 위험이 있다. 사용 목적과 고지를 정한다.

## 13. 코드·패키지·모델 파일

소스 저장소의 스크립트는 실행 전에 변경 내역, 의존성, 설치 훅, CI 설정과 Git 훅을 검토한다. 패키지 이름 유사 공격, 계정 탈취, 잠금 파일 변경과 post-install 스크립트를 확인한다. 공식 저장소·서명·해시와 재현 가능한 빌드가 있으면 활용한다.

컨테이너 이미지와 VM 이미지는 내부 레이어·기본 자격 증명·시작 스크립트·노출 포트와 베이스 이미지 지원 상태를 점검한다. 머신러닝 모델·직렬화 파일도 로드 과정에서 코드를 실행할 수 있으므로 신뢰되지 않은 pickle 등 위험 형식을 일상 분석 환경에서 열지 않는다.

## 14. 운영 절차

### 14.1 저위험 공개 파일

공식 출처와 버전·서명을 확인하고 최신 뷰어에서 연다. 해시·평판은 보조 정보로 사용한다. 예상과 다르면 중단한다.

### 14.2 내부·기밀 파일

발신자를 독립 확인하고 외부 업로드를 금지한다. 로컬·사설 정적 분석, 격리 열람과 문서 정화를 사용한다. 결과 보고서와 추출 IOC도 같은 분류로 보호한다.

### 14.3 악성 의심 파일

사용자가 반복해서 열지 않도록 격리하고 보안 담당자에게 원본 경로·전달 맥락·해시를 제공한다. 생산망에서 임의 실행하지 않는다. 이미 열었다면 단말 격리, 세션·토큰 보호와 사고 대응을 시작한다.

### 14.4 증거 파일

원본 보존, 해시, 취득자·시간·보관 위치와 접근 이력을 기록한다. 분석 사본에서 작업하고 원본을 변환·정리하지 않는다. 법적 요구가 있으면 담당 전문가와 절차를 따른다.

## 15. 자동화 안전장치

메일·업로드 파이프라인의 자동 검사는 파일 크기, 압축 깊이, 처리 시간과 메모리·디스크를 제한한다. 파서와 샌드박스를 낮은 권한·격리 컨테이너에서 실행하고 큐가 고갈되지 않게 한다. 분석 실패를 ‘정상’으로 처리하지 않고 격리·수동 검토로 보낸다.

외부 API 자동 업로드는 데이터 분류 태그와 명시적 허용 목록을 적용한다. 비밀 탐지, 개인정보 확인과 예외 승인을 두되 탐지기가 모든 기밀을 찾는다고 가정하지 않는다. API 장애·쿼터 초과 시 파일이 무검사 통과하지 않게 실패 정책을 정한다.

## 16. 검증 계획

### 16.1 기능 검증

- 이중 확장자와 MIME 불일치 파일이 격리되는가?
- 암호화 압축과 중첩 압축이 자동 통과하지 않는가?
- 매크로·외부 참조·스크립트가 기본 차단되는가?
- 기밀 분류 파일이 VirusTotal 등 공개 서비스에 업로드되지 않는가?
- 공유 링크가 지정 수신자, 만료·재공유 정책을 실제 적용하는가?

### 16.2 격리 검증

승인된 무해 테스트 파일로 VM·Sandboxie·Qubes Disposable의 네트워크, 공유 폴더, 클립보드, USB와 폐기 동작을 확인한다. 분석 환경에서 만든 표식 파일이 종료 후 호스트·다음 세션에 남는지 본다. 실제 악성코드를 생산 환경에서 시험하지 않는다.

### 16.3 복구 검증

잘못 공유된 시험 문서의 링크를 철회하고 외부 계정 접근이 거부되는지 확인한다. 다운로드 사본은 철회되지 않음을 보고서에 명시한다. 분석 시스템이 손상됐다고 가정해 깨끗한 이미지로 재구축하고 규칙·도구·증적을 복원한다.

### 16.4 오탐·미탐 검증

정상 서명 파일, 내부 개발 도구, 비정상 확장자와 무해 EICAR 같은 승인된 테스트 패턴으로 탐지 경로를 확인한다. 오탐으로 업무가 멈출 때 예외를 영구 전체 허용으로 만들지 않고 파일·서명·기간·승인 범위를 제한한다. 탐지 없음은 미탐 가능성을 남긴다.

## 17. 실패 판정

다음 중 하나면 파일 보안 절차가 구축됐다고 판정하지 않는다.

- 직원이 모든 의심 파일을 내용 확인 없이 공개 분석 서비스에 업로드한다.
- VirusTotal 탐지 0건을 안전 승인으로 사용한다.
- 샌드박스가 개인 계정·공유 드라이브와 실제 인터넷에 자유롭게 접근한다.
- 공유 링크 만료를 다운로드 사본 삭제로 오해한다.
- 서명·해시는 확인하지만 출처 채널과 공급망 침해를 고려하지 않는다.
- 파일 분석 실패나 시간 초과가 자동 정상 처리된다.
- 증거 원본을 직접 변환·실행하고 취득·접근 기록이 없다.
- 사용자가 절차가 느려 개인 메신저·USB·클라우드로 우회한다.

## 18. 사고 대응과 잔여 위험

의심 파일을 이미 열었다면 창을 닫는 것으로 끝내지 않는다. 네트워크 격리 여부를 판단하고 실행 프로세스·자식 프로세스·지속성·네트워크·다운로드·자격 증명 접근을 조사한다. 깨끗한 장치에서 관련 세션·토큰과 암호를 철회한다. 무작정 전원을 끄거나 파일을 삭제하기 전에 증거 보전과 피해 확산을 함께 판단한다.

분석 도구와 샌드박스도 취약할 수 있고, 악성 샘플은 분석을 회피하며, 정상 파일·관리 도구가 공격에서 악용될 수 있다. 수신자 장치와 다운로드 사본, 스크린샷, 클라우드 백업은 공유 철회 밖에 남는다. 따라서 파일 최소화, 출처 확인, 격리, 탐지, 최소 공유와 복구가 함께 작동해야 한다.

## 공유

수신자를 최소화하고 링크 권한·만료·다운로드 가능성·재공유를 확인한다. 암호화 파일과 암호를 같은 채널에서 함께 보내지 않는다. 해시나 디지털 서명은 전송 무결성과 발신자 확인을 보조하지만, 악성 파일이 원본 그대로라는 사실만 증명할 수도 있다.

## 검증

공유 후 외부 계정으로 실제 권한을 확인하고, 만료 시 접근이 철회되는지 시험한다. 공개 링크, 잔존 협업자, 다운로드 사본과 감사 로그의 보존 기간을 정기 검토한다.
