# DNS, 브라우저, 무선

## DNS

암호화 DNS는 단말과 선택한 재귀 확인자 사이의 질의 내용을 보호할 수 있지만 확인자는 질의를 보며, IP·시간·트래픽 분석 가능성은 남는다. 운영체제, 브라우저, VPN이 서로 다른 확인자를 쓰는지 확인하고, 공급자의 보존·관할·장애 처리 정책을 평가한다.

## 브라우저

브라우저를 최신 상태로 유지하고 확장 수를 줄인다. 사이트별 권한, 저장된 세션, 다운로드 자동 열기, 동기화 범위를 검토한다. 일반 활동은 목적별 프로필로 분리할 수 있지만, 높은 익명성 목표에서는 독특한 사용자 에이전트·확장·화면 크기 조정이 오히려 식별 신호가 될 수 있다.

## Wi-Fi와 Bluetooth

자동 연결과 불필요한 검색을 끄고, 공유기 관리자 암호·펌웨어·현대적 무선 암호화를 관리한다. 사설 MAC 주소는 추적 신호 하나를 줄이지만 네트워크 로그인, DHCP 정보, 무선 특성, 위치 서비스와 앱 SDK가 다른 연결점을 남길 수 있다. Bluetooth는 사용하지 않을 때 검색 가능 상태와 권한을 제한한다.

공용 Wi-Fi는 “사용했다”는 이유만으로 모든 암호화 통신이 즉시 노출되는 것은 아니지만, 악성 포털·잘못된 인증서 경고·근거리 관찰 위험이 커진다. 중요한 관리 작업은 신뢰 가능한 단말과 검증된 암호화 연결에서 수행한다.

## 1. 원문 항목과 현재 판단

기존 문서는 Wi-Fi와 Bluetooth가 MAC 주소를 유출하고, 클라이언트가 알려진 SSID를 브로드캐스트하며, Qubes와 Android에서 MAC을 무작위화하고 OpenWrt로 AP의 BSSID를 바꾸라고 권했다. PrivacyPolice, Smarter WiFi Manager, Privacy Friendly WiFi Manager 같은 F-Droid 앱도 제시했다. 이 문제의식은 유지하지만 2022년의 동작을 모든 현대 장치에 적용하지 않는다.

현대 운영체제는 능동·수동 스캔, 연결 전·연결 후, 네트워크별 사설 주소와 하드웨어 주소 사용 방식이 다르다. Bluetooth Low Energy도 주소 무작위화와 광고 페이로드가 별개다. MAC 하나를 바꾸면 익명해진다는 주장은 부정확하다. 네트워크 이름, 포털 계정, DHCP 옵션, 호스트명, 트래픽 시간, 무선 칩 특성, 위치 서비스와 앱 계정이 같은 장치를 다시 연결할 수 있다.

원문의 세 F-Droid 앱은 역사 자료로 보존하되 최신 Android에서의 유지·권한·호환성을 검증하지 않은 채 설치 권고하지 않는다. 오래된 네트워크 관리 앱은 오히려 넓은 위치·Wi-Fi 권한과 업데이트 중단이라는 위험을 만들 수 있다.

## 2. 관찰자와 보호 목표

무선·DNS·브라우저는 한 세션을 서로 다른 식별자로 관찰한다.

- 근처 센서와 AP는 무선 프레임, 신호 세기, 시간, 장치 주소와 연결 시도를 볼 수 있다.
- 접속망 운영자는 포털 계정, DHCP, NAT, DNS, 목적지와 사용량을 기록할 수 있다.
- DNS 확인자는 질의 이름, 출발 주소 또는 중계 정보와 시간을 볼 수 있다.
- 웹 서비스는 출구 IP, 쿠키, 계정, 브라우저·장치 특성과 행동을 결합할 수 있다.
- 브라우저 동기화·광고·분석 사업자는 여러 사이트와 장치의 식별자를 연결할 수 있다.

보호 목표를 “추적 방지”라고만 쓰지 않는다. 예를 들어 “카페 AP 운영자가 이전 방문의 같은 장치라고 판단하는 신호를 줄인다”, “ISP 대신 지정 DNS 확인자만 질의를 처리하게 한다”, “업무와 개인 세션의 쿠키·동기화를 분리한다”처럼 관찰자와 범위를 정한다.

## 3. DNS 구조와 위험

### 3.1 일반 재귀 DNS

애플리케이션은 운영체제 resolver를 통해 설정된 재귀 확인자에 질의한다. 확인자는 캐시가 없으면 루트·TLD·권한 서버 계층을 조회한다. 각 계층이 전체 이름과 사용자를 모두 알아야 하는 것은 아니지만 재귀 확인자는 사용자의 질의를 집중적으로 처리한다. 네트워크가 DNS 서버를 강제로 지정하거나 포털·보안 에이전트가 응답을 가로챌 수도 있다.

### 3.2 DoT와 DoH

DNS over TLS와 DNS over HTTPS는 단말과 선택한 확인자 사이의 질의를 암호화한다. 로컬 관찰자가 평문 질의를 직접 읽기 어렵게 하지만 확인자는 여전히 처리하고 목적지 연결 메타데이터는 남는다. DoH가 일반 HTTPS와 섞이면 검열 회피나 프라이버시에 도움을 줄 수 있지만 조직의 악성 도메인 탐지와 내부 이름 해석을 우회할 수 있다.

브라우저 자체 DoH, 운영체제 암호화 DNS, VPN DNS와 기업 에이전트가 동시에 작동하면 실제 경로가 예상과 달라진다. 정책은 어느 계층이 DNS를 책임지는지 정하고 중복 설정을 시험한다.

### 3.3 DNSSEC와 암호화 DNS의 차이

DNSSEC는 서명된 DNS 데이터의 출처와 무결성을 검증하는 체계이지 질의를 숨기는 기술이 아니다. DoH·DoT는 전송 구간을 보호하지만 응답 데이터가 권한 있는 소스에서 왔는지와는 다른 문제다. 둘을 “보안 DNS”라는 한 설정으로 혼동하지 않는다.

### 3.4 분할 DNS와 내부 이름

조직 VPN은 내부 도메인만 조직 DNS로 보내고 나머지는 로컬 또는 공용 확인자로 보낼 수 있다. 라우팅·검색 도메인·네트워크 전환이 잘못되면 내부 호스트명이 외부 확인자에게 유출되거나 내부 서비스가 실패한다. 운영체제별 resolver 상태와 실제 패킷을 확인한다.

### 3.5 DNS 공급자 평가

보존 기간, 출발 주소 최소화, ECS 사용, 관할, 필터링·차단, 장애·변조 대응, 감사와 투명성 자료를 본다. “로그 없음” 문구만으로 선택하지 않는다. 공용 확인자 하나에 모든 역할의 질의를 모으면 상관관계가 집중될 수 있다.

## 4. DNS 검증

설정 화면이나 누출 시험 사이트 하나만 보지 않는다. 승인된 시험에서 다음을 확인한다.

1. 운영체제·브라우저·VPN별 설정된 확인자와 실제 목적지가 일치하는가?
2. IPv4와 IPv6, Wi-Fi와 유선, 절전 복귀·네트워크 전환 뒤에도 같은가?
3. VPN이 끊겼을 때 DNS만 기본 회선으로 나가지 않는가?
4. 내부 이름이 공용 확인자로 전송되지 않는가?
5. 브라우저 밖 메신저·업데이터·컨테이너·VM의 DNS 경로는 무엇인가?
6. DNS 서비스 장애 시 실패가 닫히는가, 다른 확인자로 조용히 전환되는가?

패킷 캡처에는 방문 도메인과 내부 이름이 포함될 수 있으므로 접근·보존을 제한한다. 보고서에는 필요 최소한의 테스트 도메인과 결과만 남긴다.

## 5. 브라우저 보안 경계

브라우저는 웹 콘텐츠, 인증 세션, 암호 관리자, 다운로드, 카메라·마이크·위치와 클라우드 동기화를 한 프로세스 집합에서 다룬다. 최신 브라우저의 사이트 격리와 샌드박스는 중요하지만 확장, 다운로드한 파일, 외부 프로토콜 처리와 사용자 승인을 통한 경계 이동이 남는다.

### 5.1 업데이트와 배포

지원 중인 안정 채널을 사용하고 자동 업데이트 또는 짧은 패치 목표를 둔다. 브라우저 본체뿐 아니라 OS 웹뷰, PDF 뷰어, 미디어 코덱과 확장을 포함한다. 관리형 환경에서는 업데이트를 오래 지연시키는 호환성 정책과 긴급 취약점 예외 절차를 정한다.

### 5.2 프로필과 역할 분리

업무, 개인, 관리자, 조사 역할을 별도 프로필 또는 더 강한 VM·Qubes 구획으로 나눈다. 프로필은 쿠키·기록·확장을 분리하는 편의 경계지만 같은 OS 사용자, 브라우저 동기화, 다운로드 폴더, 클립보드와 악성코드에 의해 연결될 수 있다. 고위험 역할은 프로필만으로 충분하지 않을 수 있다.

### 5.3 확장 프로그램

확장은 방문 페이지 읽기·변경, 클립보드, 다운로드와 네트워크 요청 같은 넓은 권한을 가질 수 있다. 기능이 겹치는 확장을 줄이고 게시자, 권한, 업데이트 이력, 소유권 변경과 정책을 확인한다. 한때 안전했던 확장이 매각·업데이트 후 위험해질 수 있다. 개발자 모드의 비공식 확장은 명시적 승인과 코드 검토 없이 사용하지 않는다.

### 5.4 사이트 권한

카메라, 마이크, 위치, 알림, 클립보드, USB·Bluetooth, 파일시스템과 팝업 권한을 기본 제한하고 필요한 사이트에만 부여한다. 영구 허용보다 사용 시 요청을 선호할 수 있다. 다만 매번 무심코 승인하는 피로가 생기지 않게 정기적으로 허용 목록을 정리한다.

### 5.5 다운로드와 외부 앱

다운로드 자동 열기를 끄고 실제 형식·출처를 확인한다. 브라우저에서 안전하게 보인 문서를 외부 PDF·Office 앱으로 열면 다른 샌드박스와 네트워크 정책이 적용된다. Tor Browser에서는 외부 앱 열기가 직접 연결을 만들 수 있어 특히 주의한다.

## 6. 쿠키, 저장소와 세션

쿠키, LocalStorage, IndexedDB, 서비스 워커와 캐시는 로그인과 추적 상태를 유지한다. 제3자 쿠키 제한은 추적 신호 일부를 줄이지만 퍼스트파티 계정, 링크 장식, 서버 측 식별과 브라우저 지문이 남는다. 모든 쿠키를 매번 삭제하면 가용성이 떨어지고 자주 재로그인하면서 피싱 기회가 늘 수 있다.

역할별 프로필과 사이트별 데이터 정책을 사용한다. 민감 계정은 사용 후 세션 종료와 서비스 측 활성 세션 폐기를 검토한다. 브라우저를 닫는 것만으로 서버 세션이 취소되지 않을 수 있다. 동기화를 사용하면 기록·탭·암호·확장·설정이 플랫폼 계정과 다른 장치로 복제되는 범위를 확인한다.

## 7. 브라우저 지문

웹 서비스는 사용자 에이전트, 화면·창 크기, 언어·시간대, 글꼴, 렌더링, GPU, 미디어 기능, 권한, 성능과 행동을 조합할 수 있다. 개별 값이 흔해도 조합이 드물면 식별력이 생긴다. 지문을 완전히 없애겠다는 목표보다 역할 간 차이를 줄이고 불필요한 고유 설정을 피한다.

일반 브라우저에서 지문 방지 확장을 여러 개 겹치면 값이 불일치하거나 더 독특해질 수 있다. 높은 익명성 목표에서는 Tor Browser의 공통 설정을 유지하고 임의 확장·창 크기·언어 변경을 최소화한다. 지문 테스트 사이트의 “유일함” 결과는 표본과 시점에 의존하며 실제 추적 가능성의 완전한 증명이 아니다.

## 8. HTTPS, 인증서 경고와 포털

HTTPS는 브라우저와 목적지 사이의 내용·무결성을 보호하지만 도메인·접속 시간·IP와 서비스 계정은 남는다. 인증서 경고를 무시하고 진행하지 않는다. 공용 Wi-Fi 포털 때문에 경고가 나타나면 운영체제가 제공하는 포털 감지 페이지나 알려진 HTTP 테스트 주소를 사용하고, 민감 사이트의 경고를 예외 등록하지 않는다.

조직 TLS 검사 프록시는 단말에 조직 루트 인증서를 설치해 트래픽을 복호화할 수 있다. 보안 탐지 이점과 관리자·로그·개인정보 위험을 문서화하고 개인·고위험 통신의 정책을 정한다. 알 수 없는 루트 인증서와 관리 프로필을 점검한다.

## 9. Wi-Fi 식별자와 스캔

### 9.1 MAC 주소

MAC 주소는 로컬 링크 식별자다. 공인 인터넷 목적지까지 그대로 전달되는 것은 아니지만 AP와 근처 무선 관찰자는 볼 수 있다. 현대 OS의 사설 주소는 네트워크별로 안정적이거나 주기적으로 바뀔 수 있고, 기업 802.1X·장치 등록과 충돌할 수 있다. 정확한 OS·버전 동작을 공식 문서로 확인한다.

### 9.2 프로브와 알려진 네트워크

과거 클라이언트는 저장된 SSID를 능동 프로브에 드러내는 경우가 많았다. 현재는 와일드카드 스캔과 주소 무작위화가 널리 쓰이지만 숨김 SSID, 빠른 연결, 드라이버·절전 구현에 따라 동작이 다를 수 있다. 더 이상 쓰지 않는 네트워크를 삭제하고 자동 연결을 제한한다.

### 9.3 SSID·BSSID

SSID는 네트워크 이름, BSSID는 일반적으로 AP 라디오의 링크 주소다. SSID를 흔한 이름으로 바꾸거나 BSSID를 주기적으로 변경해도 물리 위치, 채널, 신호, 백홀, 포털과 트래픽 패턴이 남는다. OpenWrt 자동 BSSID 변경은 연결 실패와 관리 복잡성을 만들 수 있어 일반 기본선으로 권고하지 않는다.

### 9.4 Qubes와 VM

Qubes에서는 네트워크 하드웨어가 net qube에 연결되고 AppVM이 가상 인터페이스를 사용한다. 업스트림 AP가 보는 주소와 qube 내부 주소를 구분한다. VM 설정에서 MAC을 바꿔도 호스트 무선 장치가 외부에 제시하는 주소가 그대로일 수 있다. Qubes 공식 MAC 무작위화 문서와 실제 패킷·AP 로그로 검증한다.

## 10. 가정·소규모 조직 Wi-Fi 기준선

- 지원 중인 공유기·AP와 최신 펌웨어를 사용한다.
- 관리자 계정은 기본값을 바꾸고 원격 관리를 제한한다.
- WPA3 또는 호환성이 필요한 WPA2의 강한 구성을 사용하고 WEP·개방형 관리를 피한다.
- WPS는 업무 필요가 없으면 끈다.
- 직원·게스트·IoT와 관리 네트워크를 위험에 맞게 분리한다.
- 게스트 간 통신과 내부 관리 인터페이스 접근을 제한한다.
- DNS, NTP, 업데이트와 로그가 어느 외부 서비스로 나가는지 확인한다.
- 백업 구성과 공장 초기화·교체 절차를 마련한다.

네트워크 이름에 주소·성명·회사 역할을 넣지 않는다. VLAN은 정책 경계를 보조하지만 같은 스위치·방화벽의 잘못된 규칙과 관리 계정 침해를 막지 않는다. 무선 암호를 여러 사람에게 공유해야 한다면 개인별 802.1X 또는 별도 게스트 발급의 운영 비용을 비교한다.

## 11. 공용 Wi-Fi

공용 Wi-Fi 자체가 HTTPS 내용을 자동 공개하지는 않지만 악성 AP, 같은 이름의 이블 트윈, 포털 피싱, DNS·라우팅 조작, 로컬 서비스 노출과 물리 관찰 위험이 커진다. 연결 전 공식 SSID를 직원·표지로 확인하되 표지도 위조될 수 있음을 안다.

파일 공유·발견 기능과 불필요한 로컬 서비스를 끄고 네트워크를 공용 프로필로 설정한다. 인증서 경고와 소프트웨어 설치 요구를 거부한다. VPN이 보호 목표에 필요하면 연결 전 트래픽, 킬 스위치와 DNS를 시험한다. 중요한 관리자 작업은 가능하면 관리된 이동통신 또는 신뢰 네트워크로 미룬다.

공용망 사용을 익명성의 증거로 삼지 않는다. CCTV, 결제·회원 포털, 장치 신호, 접속 시간과 물리 동선이 연결될 수 있다.

## 12. Bluetooth와 BLE

Bluetooth Classic과 BLE는 페어링, 발견, 광고와 애플리케이션 권한이 다르다. 사용하지 않을 때 비활성화하거나 앱 권한을 제한하면 노출을 줄일 수 있지만 OS가 위치·생태계 기능을 위해 일부 스캔을 수행하는지 확인한다. 설정 화면의 토글 하나만으로 모든 무선 동작이 중단된다고 가정하지 않는다.

BLE 광고 주소가 바뀌어도 제조사 데이터, 서비스 UUID, 장치 이름, 광고 주기와 페이로드가 식별 신호가 될 수 있다. 이어폰·차량·웨어러블과 추적 장치 생태계는 클라우드 계정과 위치 기록을 만든다. 페어링 목록을 정리하고 기본 PIN·오래된 프로토콜, 불필요한 연락처·메시지 공유를 제한한다.

브라우저와 앱의 Bluetooth 권한은 특정 웹사이트·앱이 근처 장치와 통신하게 할 수 있다. 필요 시에만 승인하고 사용 후 해제한다. 조직은 회의실·출입·의료·산업 장치의 BLE를 일반 개인 장치 정책과 구분한다.

## 13. 모바일 위치와 무선 권한

Wi-Fi·Bluetooth 스캔은 위치 추정과 주변 장치 기능에 사용될 수 있다. Android와 iOS의 권한 이름·백그라운드 동작은 버전마다 바뀐다. 위치 권한, 정확한 위치, 근처 기기, 백그라운드 새로 고침과 시스템 위치 서비스를 앱별로 검토한다.

위치 서비스를 꺼도 이동통신 기지국, IP, 사진 배경, 시간과 계정 사용이 위치 단서를 남긴다. 반대로 무조건 모든 위치 기능을 끄면 긴급 구조, 지도·분실 장치 복구와 업무 안전을 해칠 수 있다. 역할·상황별 보호 목표로 결정한다.

## 14. 참조 아키텍처

### 일반 개인

지원 중인 공유기, WPA2/3, 자동 업데이트, 목적별 브라우저 프로필, 최소 확장과 운영체제 기본 사설 Wi-Fi 주소를 사용한다. 공용망에서는 인증서 경고를 무시하지 않고 민감 작업을 줄인다.

### 소규모 팀

관리·직원·게스트·IoT를 분리하고 개인별 계정과 로그 보존 최소화를 적용한다. 조직 DNS와 브라우저 정책은 악성 차단 목적, 보존 기간, 예외와 개인정보 접근자를 문서화한다. 관리자 브라우저는 일상 웹과 분리한다.

### 고위험 역할

전용 단말 또는 Qubes 구획, Tor Browser 기본값, 승인된 네트워크 경로, 역할별 계정·시간·데이터 이동 규칙을 적용한다. MAC 변경 하나에 의존하지 않고 물리 위치·계정·행동 상관을 함께 관리한다.

## 15. 검증 절차

### DNS

테스트 도메인을 사용해 운영체제, 브라우저, VPN, VM·컨테이너의 실제 질의 목적지를 캡처한다. 네트워크 전환, 절전 복귀, VPN 장애, IPv6와 내부 이름 조건을 반복한다.

### 브라우저

업데이트 버전, 확장·권한·동기화 목록, 역할별 프로필의 쿠키·다운로드·클립보드 교차 여부를 확인한다. 시험 계정의 세션을 종료하고 다른 프로필에서 재사용되지 않는지 본다.

### Wi-Fi

승인된 AP 로그와 무선 캡처로 연결 전·후 주소, 네트워크별 사설 주소, 자동 연결과 알려진 SSID 동작을 확인한다. 캡처에는 주변 제3자 장치가 포함될 수 있으므로 법적 권한·범위와 보존을 제한한다.

### Bluetooth

앱 권한, 발견 가능 상태, 페어링 목록과 사용하지 않는 서비스가 꺼지는지 확인한다. 무해한 시험 장치로 재부팅·업데이트 뒤 설정이 유지되는지 본다.

## 16. 실패 판정

다음 중 하나면 통제가 완성되지 않았다.

- DNS 설정 화면만 보고 실제 쿼리 경로를 시험하지 않았다.
- VPN 연결 중 브라우저 DoH나 IPv6가 다른 경로를 쓴다.
- 업무·개인·관리자 브라우저가 같은 동기화 계정과 다운로드 폴더를 공유한다.
- 추적 방지 확장을 많이 설치해 더 독특한 브라우저가 됐다.
- MAC 무작위화를 완전한 익명성 통제로 보고 포털·계정·위치 기록을 무시한다.
- 오래된 F-Droid 네트워크 앱을 유지 상태 확인 없이 설치한다.
- 게스트·IoT에서 관리자 인터페이스와 업무 장치에 접근할 수 있다.
- 인증서 경고를 공용 Wi-Fi 포털 탓으로 돌리고 예외를 저장한다.

## 17. 사고 대응과 잔여 위험

악성 AP·포털에 자격 증명을 입력했거나 인증서 경고를 우회했다면 네트워크를 잊는 것만으로 끝내지 않는다. 깨끗한 장치에서 관련 암호·세션·토큰을 철회하고 설치된 인증서·프로필·앱과 DNS·프록시 설정을 점검한다. 조직 장치는 보안 담당자에게 시간·장소·SSID·관찰 내용을 보고한다.

무선 주소와 브라우저 설정을 바꿔도 계정, 문체, 시간, 위치, 결제와 상대방 기록이 활동을 연결할 수 있다. 암호화 DNS도 확인자와 목적지 연결을 제거하지 않는다. 브라우저 샌드박스와 사이트 격리도 악성 확장·사용자 승인·OS 침해를 완전히 막지 않는다. 이 장의 통제는 식별 신호와 공격면을 줄이는 수단이지 완전한 익명성 보증이 아니다.
