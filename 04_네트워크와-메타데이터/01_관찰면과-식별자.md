# 관찰면과 식별자

## 관찰자 지도

로컬 네트워크 운영자, 인터넷 제공자, VPN·DNS 사업자, 목적지 서비스, 광고·분석 SDK, 결제·통신 사업자, 협업 상대가 서로 다른 정보를 본다. “암호화됨”이라는 한 단어 대신 각 관찰자가 보는 필드, 보존 기간, 계정 연결 가능성을 적는다.

## 식별자의 결합

후보를 좁히는 단서는 고정 식별자만이 아니다. 접속 시간과 파일 크기, 언어·시간대, 브라우저 기능 조합, 타이핑과 게시 습관도 쓰인다. 식별자 하나를 바꿔도 나머지 신호가 그대로라면 연결 가능성은 남는다. 지나친 무작위화는 드문 구성을 만들어 지문을 도드라지게 할 수도 있다.

## 최소화 전략

필요 없는 수집과 동기화를 끄고, 계정 목적에 맞게 브라우저 프로필과 저장 데이터를 분리한다. 기록이 필요한 경우 접근자, 보존 기간, 삭제 조건을 명시한다. 네트워크 경로를 자주 바꾸는 것보다 동일 신원을 여러 경로에서 사용하는 방식이 어떤 상관 신호를 만드는지 먼저 평가한다.

## 검증

데이터 흐름도에서 각 경계별로 평문 내용, 암호화된 내용, 주소·시간·양, 계정 식별자, 단말 식별자, 결제 정보를 표시한다. 정책 문서만으로 알 수 없는 서버 측 기록은 미확인 가정으로 남긴다.
