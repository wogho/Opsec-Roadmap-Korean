# OPSEC 지식그래프 허브

central:: [[00_백서-안내/03_기준-위협-모델|기준 위협 모델]]

canvas:: [[00_백서-안내/OPSEC 관계성 지도.canvas|OPSEC 관계성 지도]]

evidence:: [[05_참고문헌|참고문헌]] · [[07_품질-검증|품질 검증 기록]]

이 허브는 백서의 목차가 아니라 의사결정 관계를 나타내는 인터페이스다. 각 문서는 적어도 하나의 위협, 통제, 운영 절차 또는 검증 증거와 연결되어야 한다. 연결이 없는 문서는 범위와 유지 책임을 다시 검토한다.

## 관계 의미

| 관계 | 출발 노드 | 도착 노드 | 해석 |
|---|---|---|---|
| `drives` | 위협 모델 | 위험 평가 | 자산·상대·공격 경로가 우선순위를 결정 |
| `selects` | 위험 평가 | 통제 영역 | 위험 처리 결정이 필요한 통제 묶음을 선택 |
| `depends_on` | 통제 | 다른 통제 | 한 통제의 효과가 다른 통제나 신뢰 경계에 의존 |
| `operationalized_by` | 통제 | 운영·대응 | 설계 통제를 변경·관측·복구 절차로 구현 |
| `verified_by` | 통제·운영 | 근거·시험 기록 | 효과와 한계를 출처 또는 시험 결과로 확인 |
| `updates` | 검증 결과 | 위협 모델 | 실패, 환경 변화와 잔여 위험을 다음 평가에 반영 |
| `tailored_by` | 적용 프로파일 | 위험 평가·통제 | 사용자 유형과 환경이 기준선의 강도를 조정 |

## 탐색 방법

1. 새로운 운영 환경은 [[03_위협-모델-워크시트|위협 모델 워크시트]]에서 시작한다.
2. [[00_백서-안내/OPSEC 관계성 지도.canvas|Canvas]]에서 관련 통제 영역과 운영 노드를 좁힌다.
3. 개별 문서의 내부 링크와 Backlinks로 선행 조건과 파급 범위를 확인한다.
4. 통제 적용 후 시험 결과와 잔여 위험을 기록하고 위협 모델의 가정·공격 경로를 갱신한다.

Graph View는 전체 Vault의 링크 구조를 탐색하는 보조 도구다. 링크 수나 중심성은 통제의 중요도 또는 효과를 증명하지 않는다. 보안 판단은 위협 모델, 검증 증거와 위험 수용 기록을 기준으로 한다.
