# 패치와 소프트웨어 공급망

## 설치 기준선

지원되는 소프트웨어만 유지하고 공식 저장소·공급자 채널을 우선한다. 설치 전 게시자, 서명, 해시, 릴리스 출처를 확인하되 해시는 같은 손상된 사이트에서 가져오면 독립 검증이 아니다. 사용하지 않는 브라우저 확장, 원격 관리 도구, 개발 런타임은 공격면을 늘리므로 제거하거나 격리한다.

## 업데이트 정책

브라우저, 운영체제, 메시징, 문서 뷰어처럼 외부 입력을 처리하는 구성요소는 자동 보안 업데이트를 기본으로 한다. 업무 중단 위험이 큰 시스템은 짧은 시험군을 거치되, 긴 승인 대기 자체가 위험이 되지 않도록 최대 지연 시간을 정한다. 지원 종료 제품은 보완 통제만으로 무기한 유지하지 않는다.

## 공급망 위험

패키지 이름 혼동, 빌드 계정 탈취, 자동 업데이트 채널 침해, 악성 확장과 의존성을 고려한다. 필요한 출처와 관리자 수를 줄이고, 잠금 파일·서명·재현 가능한 빌드 정보가 있으면 활용한다. 설치 스크립트를 셸에 바로 연결하기 전에 내용을 검토하고 버전을 고정한다.

## 검증

월별로 미지원 버전, 실패한 업데이트, 새 자동 실행 항목, 관리자 권한 앱을 확인한다. 공급망 사건이 발생하면 버전·해시·설치 시점·영향 단말을 재현할 수 있어야 한다. 민감 파일을 공개 분석 서비스에 업로드하면 제3자에게 공유될 수 있으므로 [파일 검증 절차](../05_데이터와-암호화/04_파일-수신-검증-공유.md)를 따른다.
